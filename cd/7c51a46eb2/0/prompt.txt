This is the single most dangerous property of the whole operation.

## B. The rewrite

Three preparation steps, then one filter-repo call.

```bash
# 1. drop the ephemeral entire.io shadow branches (worth ~2.1 GB; sanctioned by the CLI)
entire clean --all

# 2. commit the held-back untracking (already staged)
git commit -m "Untrack the 30 held-back HEIC/thumbnail files (see .gitignore)"

# 3. generate the OID list: every reachable blob &gt;=1 MB that is in NO local branch tip
#    (script: scratchpad/rewrite/mkpurge.py — asserts the purge set is disjoint from every tip)
python3 mkpurge.py     # -&gt; purge-oids-final.txt

# 4. the rewrite
git filter-repo --strip-blobs-with-ids purge-oids-final.txt --prune-empty never --force
```

Design choices, each deliberate:

- **`--strip-blobs-with-ids`, not `--path`.** Path removal cannot keep the tip version of a still-shipping file — it would delete `spatial_m31_andromeda.heic` outright. OID stripping keeps the tip and removes exactly the superseded blobs.
- **`--prune-empty never`.** Keeps the commit DAG 1:1 (112 commits before, 112 after), which makes verification trivial and avoids reshaping the entire.io checkpoint chain.
- **1 MB threshold.** Superseded *source* versions are legitimate project history and are worth 1.79 MB in total. They are kept.
- **Transcript blobs excluded from the list.** 22 superseded `full.jsonl` blobs worth 0.6 MB were dropped from the purge set. Including them rewrote `entire/checkpoints/v1`'s SHAs; excluding them leaves that branch **bit-identical**. 0.6 MB is a trivial price for not touching the entire.io mirror branch at all.

## E. Risks and open questions

**Decide before cutover**

1. **Is ~340 MB worth a force-push?** Steps 1–7 give 6.1 of the 6.45 GB with none of the risk. My recommendation is to do steps 1–7 now and treat the rewrite as optional.
2. **The bloat will come straight back.** entire.io's shadow branch snapshots the entire working tree — including 1,482 MB of *untracked* files (only 2.3 MB of the 1,484 MB snapshot is gitignored, and that 2.3 MB is entire.io's own metadata, which it force-includes). Expect `.git` to regrow 1.5–3 GB per active session. Without a fix, you will be doing this again in a fortnight. `entire configure` (CLI 0.8.42) exposes no exclude or size-limit flag. Options worth raising with entire.io: whether shadow branches can respect `.gitignore`, and `--checkpoint-remote github:darthzen/float-checkpoints` to move the 370 MB transcript branch out of this repo. **I could not verify whether gitignoring `upscale/`, `_raw/`, and `screenshots/` would actually stop the snapshotting — it demonstrably includes at least some ignored paths.**
3. **The "29 shipping HEICs" discrepancy.** HEAD has 51; 36 remain after untracking 15. The brief says 29. Reconcile against `premiumHeldBack` in `SpatialImageEnvironment.swift`, `project.yml`'s `excludes:`, and `.gitignore` (the CLAUDE.md three-list invariant, checkable with `scripts/offload_cold.py --check`) before trusting any count. This does not affect rewrite safety — the rewrite is OID-driven and preserves every tip blob regardless — but it may mean a further set of files should be held back first.
4. **9 HEICs are in HEAD but deleted from the working tree**, and 27 more are modified on disk (often much larger than committed, e.g. `spatial_m31_andromeda.heic` is 79.8 MB on disk vs 18.5 MB committed).
