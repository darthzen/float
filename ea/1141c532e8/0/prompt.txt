## Head pose

`WorldTrackingProvider.queryDeviceAnchor(atTimestamp: CACurrentMediaTime())` → `DeviceAnchor.originFromAnchorTransform`, queried on demand at button press only (nothing polls per frame). Verified against the XROS27.0 SDK `.swiftinterface` that this is still the current signature. `NSWorldSensingUsageDescription` was already in `Info.plist`, so no plist/entitlement change was needed.

Yaw extraction: take the `-Z` column of the device transform, keep only its `(x, z)` components, and `atan2` that — dropping `y` *is* the yaw-only extraction, so pitch and roll never reach the quaternion. The rotation is written to `sceneRoot.orientation` as `simd_quatf(angle:axis: [0,1,0])`, which composes with (does not touch) the sphere's canonical `-π/2` facing in `makeSphere()`. Instant snap, no animation, no clock involvement — so the §5 one-clock rule isn't engaged at all. The camera is never touched.

Two guards: a press is ignored if the device anchor isn't tracked, and ignored if the horizontal projection of forward is degenerate (user staring near-straight up or down), rather than snapping to an arbitrary heading.

## Decision: recenter persists across scene changes

The yaw lives on `sceneRoot`, the persistent `SpatialImageEnvironment` container; `load(index:into:)` only replaces the child sphere. So a scene switch inherits the current recenter for free. This is deliberate and I think correct — the yaw describes which way the user's *body* is pointing, not anything about a particular sky, and having the world jerk back to an arbitrary heading mid-session on a scene swap would be both surprising and a comfort regression. It resets on app relaunch (session-only, no persistence added, as scoped).

One thing worth your call: I'd argue this *should* persist across launches too, for the common case of a user with a fixed favourite chair. That's a one-line `UserDefaults` addition next to the existing `lastSceneKey`. Not implemented — flagging rather than doing, per scope.
